After filling, convert it to an integer.

## 2. Duplicates (`duplicates.csv`)

- 25,902 rows are exact duplicates of another row (32.65%).
- The file has no booking ID, so two real, different bookings can look identical
  (same dates, same price, same customer type).
- Risk if kept: if the same row lands in both train and test, the test score
  looks better than it really is.
- Suggestion: remove exact duplicates (keep the first copy) before splitting
  into train and test. This is a team decision, because it removes about a third
  of the data. Mohamed Ashraf to confirm.

## 4. Types and cardinality (`column_types.csv`, `cardinality.csv`)

| Column | Unique values | Problem | Suggestion |
|---|---|---|---|
| ReservationStatusDate | 864 | A date stored as text, not a category. Also set after the booking outcome. | Parse as a date. Tervina to decide if it is leakage. |
| Agent | 223 | An ID, not a number. Too many values for one-hot encoding. | Treat as categorical. Group rare agents into `Other`. |
| Company | 207 | Same as Agent. | Use a "has company" flag, or group rare ones. |
| Country | 166 | Too many values for one-hot encoding. | Group rare countries into `Other`. |

Other text columns have 12 or fewer values (ArrivalDateMonth 12, AssignedRoomType 9,
ReservedRoomType 8, MarketSegment 8, DistributionChannel 5, Meal 4, CustomerType 4,
DepositType 3, ReservationStatus 3). One-hot encoding is fine for them.

## 5. Points for the leakage audit (for Tervina)

- `ReservationStatus` and `ReservationStatusDate` are recorded at the end of the
  booking, so they reveal the final outcome.
- `AssignedRoomType` and `BookingChanges` can change after the booking is made.
